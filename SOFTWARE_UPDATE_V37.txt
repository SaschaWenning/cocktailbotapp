CocktailBot V37 – Update aus den Einstellungen

UI:
  Einstellungen -> Software-Update -> Update installieren

Nur direkt am Raspberry:
  POST /api/system/update akzeptiert ausschließlich Loopback-Requests.
  Ein Tablet oder PC im LAN darf den Update-Root-Vorgang nicht auslösen.

Sicherheitsmodell:
  cocktailbot.service läuft weiterhin als normaler CocktailBot-Benutzer.
  In /etc/sudoers.d/cocktailbot-update wird ausschließlich freigegeben:
      /usr/local/sbin/cocktailbot-update-launcher
  Es gibt KEIN allgemeines NOPASSWD-sudo für den Benutzer.

Ablauf:
  1. Backend stoppt laufende Pumpenjobs.
  2. Backend startet per sudo den fest installierten Launcher.
  3. Launcher erzeugt eine eigene systemd-Unit cocktailbot-self-update.
  4. Worker führt aus:
       git -c safe.directory=/opt/cocktailbot/source          -C /opt/cocktailbot/source fetch origin main

       git -c safe.directory=/opt/cocktailbot/source          -C /opt/cocktailbot/source reset --hard origin/main

       bash /opt/cocktailbot/source/tools/update.sh

       systemctl reboot

  Neustart erfolgt nur, wenn fetch/reset/update.sh erfolgreich waren.

Log:
  /var/log/cocktailbot-update.log
