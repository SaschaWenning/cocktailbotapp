CocktailBot Pi 5 – Offline/Web-Release Sync Fix V3

Purpose
-------
The installer no longer blindly installs whatever happens to be present on the
web-release branch.

GitHub Actions writes .cocktailbot-release containing:
- source_sha
- app_tree_sha
- workflow_sha256
- built_at_utc
- offline_canvas_kit=1

install.sh compares app_tree_sha and workflow_sha256 with the current main
checkout. If the web-release is still stale while GitHub Actions is building,
the installer waits (default: 600 seconds), refetches web-release, and only
continues once the release matches.

Before replacing /opt/cocktailbot/web it additionally verifies:
- index.html and main.dart.js
- local CanvasKit JS/WASM
- "useLocalCanvasKit":true
- canvasKitBaseUrl: "canvaskit/"

A failed/stale release is rejected before the installed web directory is
replaced.

Environment tuning:
  COCKTAILBOT_WEB_RELEASE_WAIT_SECONDS=600
  COCKTAILBOT_WEB_RELEASE_POLL_SECONDS=10

Source builds are also forced to use:
  flutter build web --release --no-web-resources-cdn
and a local canvasKitBaseUrl, so tools/update.sh cannot accidentally restore
the original online CanvasKit dependency.
